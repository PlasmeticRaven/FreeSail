## What this is

Today a new player installs Python, types `py -m pip install -e ".[dev,server,agents]"` at a prompt, and then `py -m freesail`, which starts the game's server and opens the harbour in his browser. The owner does this; his friends will not. **Wanted: a player who has never heard of Python downloads one file, unpacks it, opens one thing, and the harbour is in his browser.** Nothing of the game itself changes.

1. **Windows (64-bit, 10 and 11): a folder that carries its own Python.** One zip. Unpacked anywhere the player can write (his Downloads, his Desktop, a path with spaces and non-English letters in it), it holds a private Python (python.org's embeddable distribution, a pinned version, its checksum verified at the build), the game's dependencies installed into it (what `py -m freesail` and a game begun from the harbour need: the base and the `server` extra; say in the report what the `agents` extra adds and whether you ship it, so that a player who later wants a model at a station is not stopped; never `dev`), the game (`freesail/`, `data/`, `client/`, and whatever else it opens when it runs: find that out, do not guess), and ONE thing to open: a launcher at the top of the folder named so that a newcomer picks it ("FreeSail", with the right kind of file behind it), which starts the game with the private Python and nothing from the machine's own PATH or registry, leaves a window that says in plain words what is happening and how to stop, and lets `python -m freesail` open the harbour as it does now. A machine with another Python installed, or none, behaves the same.
2. **Mac (Apple silicon and Intel, macOS 12 and later): the same promise, by whatever road truly works unsigned.** The owner has no Mac, and neither do you: **the evidence is a Mac in the cloud** (GitHub's macOS runners, both architectures; the repository is public, so they cost nothing). A Mac's Gatekeeper quarantines what a browser downloads, and an unsigned bundled interpreter with its libraries may be refused outright; a script that fetches its interpreter itself is not quarantined but needs the network once. Research it, choose, and say why in the report: a relocatable Python carried in the download, or fetched and verified by checksum at first start, or the player's own Python 3.11+ if he has one with a clear word if he has not. Whatever you choose, what the player does must fit in three short steps on the "start here" page, including the one-time "this was downloaded from the internet" step, in the words macOS itself uses.
3. **A "start here" page** at the top of each download, plain text and short (a screen): how to start; the one-time warning each system gives for a program with no known publisher and how to pass it; what he will see (a window with the game's server, and the harbour in his browser; begin with *A first passage*); how to stop; where his saves and settings live (the game already keeps them in his own data folder, outside the unpacked folder: confirm it on both systems and say the paths) and so how to take a newer download without losing them; where to tell the owner what went wrong. In the plain words of a manual for someone who sails and does not program. It names no AI vendor or model: a model at a station is "optional, and needs a key of your own; see the README".
4. **Built by the repository's own workflows, and proven there.** (a) A script in `tools/` that assembles each download from a checkout, deterministic in what it includes, every third-party download pinned by version AND checksum (the interpreter; the dependencies from a lock file with hashes, installed with `--require-hashes`), with the third parties' licence texts kept in the download. (b) The gate's release (`.github/workflows/release.yml`) attaches both downloads beside the zip of the project it attaches today. (c) A workflow the owner can run by hand on any branch ("Run workflow", a name typed) that builds both downloads and publishes them as a pre-release for handing to friends between gates. (d) **A smoke test that runs in the cloud on Windows and on both kinds of Mac against the built download itself, unpacked in a fresh folder whose path has a space in it, with the runner's own Python hidden from it:** it starts the game by the launcher's own road, waits for the server, asks the harbour's page and its API for what a player's first click asks, begins *A first passage*, runs a minute of the game's time, reads a primer chapter, saves, stops it cleanly, and checks that nothing was written inside the unpacked folder and that the save lies in the user's data folder. Its findings are said in lines a person can read without downloading a log (GitHub's `::notice::` and `::error::` annotations and the job summary), because the lead reads them through the public API.
5. **A test in the ordinary suite** that the download's list of files holds everything the game opens: with Python's audit hook on file opens, start the server's app, begin a shipped scenario, run it a minute, serve a primer chapter and a chart's tile, save; every file opened under the repository lies in the list the assembling script would ship. So that a file added to the game next month and forgotten by the packer fails a test and not a friend's first evening.
