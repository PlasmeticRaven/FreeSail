# Milestone 4 work packages: contracts between them

Milestone 4 is specified in `docs/TechnicalSpec-M4.md` in three parts with three gates. Read it whole before your section, then `docs/agents/README.md` (the commitments to models, which are requirements) and the milestone 3 and 3b working rules (`docs/dev/M3-WorkPackages.md`, `M3b-WorkPackages.md`), which hold: stay inside your files, build what the specification says at the size it says, every number names its source, physics before rules, deterministic, ship's-log voice, run the whole suite and read the summary line yourself, report in the set order. Packages are scoped for a senior engineer: leeway in how, and a little beyond the letter where the specification's intent is served, said so in the report.

Two rules added for this milestone:

- **Parity is structural.** Anything a standing order can test, an instrument can show and an agent can ask for, through one registry. Do not add a reading in one place only.
- **Prove the harness with the fake before a model.** No package's tests call a language model. Every commitment to models (`docs/agents/README.md`) has a test against the scripted fake.

## Package 28d: the shelf (spec M4 open item 9, the context work; `freesail/agents/tools.py` for `library` and the new `shelve` tool, `harness.py` for shelving and the shelf-life, `remote.py` and `local.py` for the runner rebuilding its messages from the shelved stream, `repl.py`, `tools/context_budget.py` new, `docs/agents/Harness.md`, `docs/agents/README.md`, `tests/test_agents.py`, `tests/test_local_runner.py`, `tests/test_context_budget.py` new). Opus. Starts when 28c has landed; the gate is cut on both.

The design (owner and lead, 2026-09-28): a library read is a book taken off the shelf, and the reader puts it back.

- **The shelf lists sizes and sections.** `library(topic='contents')` says what each topic costs in tokens (measured at four characters a token from the text actually served; the lead measured chapter 3 at about 7,650 tokens and "the ship" at 3,800); `library(topic='primer 3')` returns the chapter's headings with their sizes; `library(topic='primer 3', section='reefing')` returns one section; `library(topic='primer', find='goose-wing')` returns the paragraphs that match, with their chapter and section. The catalogue and the ship's names get sections too (an evolution; a mast's parts).
- **Every read has a handle**, opening the result: "primer 3, reefing, opened 04:10; book 7". A large `read_log` is a book too.
- **The reader shelves it.** A tenth tool `shelve(book)` (a handle, a topic name, or nothing for all open books): from the next request on the body is gone from the conversation and only the handle line remains ("you read primer 3, reefing, at 04:10"); reading again reopens it. The journal is where the reader keeps what it took from the page; the brief says so.
- **A shelf-life as the backstop**: a book left open goes back after a fixed number of the model's own turns (`SHELF_LIFE_TURNS`, three, judgement named), stub in its place; the brief and the tool's description say the number.
- **Where it works**: in-process, the API, the runner (which rebuilds its messages from the game's turn stream on each request, so a shelved turn is served as its stub) and the REPL; over an MCP client the model's conversation lives in the app, so `shelve` answers honestly that the client keeps its own conversation and the journal habit still carries. Replay is untouched: a shelve is a reply in the transcript, and the shelf-life counts the model's turns.
- **The reference is a promise, not a possession** (`docs/design/Papers-and-Books.md`): the reference library stays always reachable; the ship's own papers, in-world, are later milestones' and will use the same shelf.
- **`tools/context_budget.py`** (open item 9a): reads a GGUF header (layers, key-value heads, head width, size on disk) and prints the KV-cache bytes per token at f16 and q8_0 and the largest `--ctx-size` that fits a card's memory after the weights and a headroom; `Harness.md` gains the table the owner fills from it; the owner's observed range for the two 26B and 27B models (80k to 110k on a 4090) is the check.
- **The handover** (open item 9b) is *not* in this package; it follows when a session has actually run long enough to need it.
- Tests against the fake: sizes and sections served; a read, a shelve, the stub in the next request's messages on the runner; the shelf-life; `read_log` shelved; the MCP answer; the budget script on a synthetic header.

The owner's ruling on the reef that belayed the take-in of the topgallants (finding 2), given 2026-09-29 and to be changed as little as possible: **a call for all hands is a pool action, separate in type from work orders, like piping down.** It turns the watch below up and changes who is on deck; it does not otherwise interact with the work in hand. Orders start in book order and keep the hands they got; an all-hands evolution takes the idle hands and everyone coming up, and as earlier work finishes its hands join it (the top-up already does this every tick); work that cannot get hands waits and starts as hands come free. Nothing already in hand is belayed by a later all-hands call to work sail. Manoeuvres are the carve-out, ruled the same day: a tack, a wear, a boxhaul or lying a-try still takes the ship's whole attention and belays the sail work in hand as before ("Ready about" stops the work; truth 19 stands), because the lead showed the belay there is one condition and keeps the change smaller, and a party hoisting a royal while the ship goes about is not seamanship. The reef still pipes the hands down when it ends unless the captain called them.
