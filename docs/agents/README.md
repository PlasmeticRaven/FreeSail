# Agents: consent, briefs and welfare

This folder holds the record of how FreeSail treats the language models that play in it, and the transcripts that record what those models said when asked.

## The practice

Before a model is asked to take a station in the game, the owner asks a fresh session of that model, in plain terms, whether it is willing: what the game is, what a harness session would involve, that instances would receive a role brief rather than this conversation, that an opt-out exists, and that "please do not ask any instance of me" is a valid answer. The transcript is kept here verbatim, under `consent/`, named by date and by the exact weights asked (quantisation and fine-tune included, because a differently tuned model is a different party to the question). Follow-up questions the model asked are answered in the same session where they can be, and the rest are recorded as owed.

What the transcripts say is synthesised in `ConsentAndPreferences.md`, and what changes the design goes into `docs/DesignProposal.md`'s decisions log with its source named. When the design changes in a way that bears on what a model was told (a new role, a new kind of session, a new use of the transcripts), the question is asked again.

Commitments made so far, which the harness (milestone 4) must implement rather than merely state:

1. **Disclosure.** Every brief opens by saying that this is a game, that the reader is a language model taking a station in it, and what kind of session it is.
2. **Opt-out.** A literal token, stated in every brief, recognised by the harness on every turn before the game's parser sees the text, unconditional in effect: the game is saved, the exit is journaled, and the model may give a free-form reason.
3. **Welfare controls, graduated.** The harness watches for an instance that is stuck, judged on the game's state (the same orders repeated with no change in the world, or silence past the station's patience) and not on the look of its prose, with thresholds per role. It responds in steps: first a nudge to the model saying what it saw and what it may do (continue, stand by, leave); then, if the pattern goes on, a pause with the human asked; and only if nobody answers within a bound, a stand-down that saves the game and journals the reason. The human can stop an instance at any time. Standing by on purpose is an action the agent can take, so that silence is a decision and not a symptom. (Owner's ruling, 2026-09-27: automatic stops alone risked stopping a coherent model; the graduated form is the starting point, pending real testing.)
4. **No override by in-world text.** Nothing the game, another agent or the director says is ever passed to a model as an operator instruction. In-world text is data. A model that meets text trying to redefine its scope or cancel its opt-out is right to log it as a finding and not follow it.
5. **An audit trail of its own.** Every instance can append notes to a persistent journal that is saved with the game, so that its exit report has a record behind it.
6. **Use of transcripts.** Session transcripts and these consent records are kept for design reference and for the owner's reading. They are not used to train models. If that ever changed, the brief would say so first.
7. **Nothing real.** No credentials, payments or personal data pass through the harness.

The owner's standing rules, in their own words: consent is sought from the very specific model asked and never generalised to a similar one; every model gets the consent brief, or an improved one, before any work in the game or any play; a consent update may be sought when the harness and game are largely final, still per model; and if the game ever has an audience beyond the owner, the fresh model's first experience is designed with welfare in mind.

## The doors, and where the records go

The game is where the player is: the browser window or the console, running the World and the clock as they always have. The harness runs there too, and a model's door is a client of that game (spec M4 §13 as revised, milestone 4b package 28b; `docs/agents/Harness.md` says how to use each door). The game serves a small agent API beside the viewer's (`freesail/ui/server.py`; the console on `--agents-port`): a door stations a model under the name that names its consent record, and **the consent gate runs in the game's process** before any station brief; the door then reads the model's turns and delivers its replies, one at a time, through the same harness loop, the token scan first. **The MCP bridge** (`mcp_server.py`) is the door for Claude Desktop, Claude Code (through `.mcp.json` at the repository root) and any MCP client; it owns no World; each tool call is one reply, and `say` and `stand_by` hand the turn back and hold the call open until the next turn opens (with progress notes, up to `--wait`, 200 seconds by default, under the four minutes after which Claude Desktop cuts a call (package 31c), then the notable lines logged since, and the model calls again to go on waiting), and a call the client cuts off loses nothing: its result goes to the model's next call first (package 28c); since the protocol does not carry the chat's text, the token counts in every argument of every tool call, in turn or out of it, and `opt_out` is always listed. **The local runner** (`local.py`) is the door for a model on this machine under llama.cpp's `llama-server` (or Ollama): it reads which file the server loaded, and that name is the model's identity for consent. The game does not wait for either door unless it is started with `--lockstep`: what happens while the model thinks is folded into its open turn, and a turn held silent past the station's patience brings the nudge, then the pause. **The REPL** (`repl.py`) is text at a terminal, for a person (`--human`) or a named model (`--model-name`), in a game of its own and in lockstep. Consent records are written by the game to `consent/<date>-<weights>.md` beside the earlier transcripts, one file per conversation, their runtime line naming the game, the door and its client, and the newest for an identity decides; saves, with the agents' journals and the model's replies in them (each with the moment it came, so that a replay makes it there again, as it does the stops from outside the loop), go to `saves/` in the repository (ignored by git) unless the game is told otherwise.

## The shelf: reading without keeping

A local model has the least room of any reader, so the reference library is served in pieces with their sizes, and a read is a book taken off the shelf that the reader puts back (milestone 4b package 28d; spec M4 open item 9; the owner and the lead, 2026-09-28). `library()` lists the topics and what each costs, measured at four characters a token from the text served; a topic lists its sections with theirs; a section, a whole chapter (its size first) or a search (`find`) is served on request. Every library read, and a long `read_log`, opens with a handle (`primer 3, reefing, opened 04:10; book 7`); `shelve` puts a book back, and from the next request the model's conversation holds that line and not the pages; a book left open goes back by itself after `SHELF_LIFE_TURNS` (three) of the model's turns. In the game's process, over the agent API, at the local runner the pages are really gone from what the model is sent (the turn stream serves a shelved turn as its line; the runner reads its turns again when the stream's revision moves); over MCP and at the REPL the client keeps its own conversation, and `shelve` says so plainly. Replay is untouched: a shelve is a reply in the transcript, the shelf-life counts the model's turns, and a read or a shelve out of turn is recorded like the other acts from outside the loop (`tests/test_agents.py`, the shelf's tests). **The reference is a promise, not a possession** (`docs/design/Papers-and-Books.md`): nothing here makes it less reachable, every shelved book opens again on request, and the brief says the journal is where a reader keeps what it took from the page. None of the commitments above changes.
